# Milestone 6 report: microphone fallback, Safari/iOS handling

## What works
- Microphone input with Spotify Basic Pitch (Apache 2.0) in a worker; capture
  worklet → resampler (windowed sinc, 22.05 kHz) → model → streaming onset
  decoder → input bus. Polyphonic; velocity estimated.
- "Less accurate" labelling in Setup, a banner while listening, and on the
  practice stage; detection delay is measured and scoring waits for it.
- No Web MIDI (Safari, iOS): banner explains why, mic is the default mode and
  offered in one click; on-screen and computer keys keep working.
- Bluetooth-like output latency warning and output-change prompt (tested).
- iOS audio session handling; native MIDI path documented.

## Measured (headless Chromium, fake mic playing Salamander C4/A4/F♯4)
| What | Result |
|---|---|
| Notes recognised | exactly C4, A4, F♯4 every loop, no extras |
| Onset spacing vs truth (1000 ms) | 998.5 / 1001.5 ms |
| Analysis time per 2 s window, software WebGL | ~1.25 s (CPU backend ~1.8 s) |
| Detection delay here | ~5 s, because of software GL |

## Known issues
- Real-GPU inference speed is unmeasured; on this container the detector is
  slower than real time, so delay is seconds, not the ~0.5 s it is designed for.
- App sound (auto-played hand, video) can be picked up; headphones advised.
