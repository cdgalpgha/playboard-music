# Milestone 5 report: YouTube search and embed, sync map, Original and Karaoke

## What works

- **Search** (`video/youtube-search.ts`): YouTube Data API v3 with
  `type=video`, `videoEmbeddable=true`, `videoSyndicated=true`; durations from
  `videos.list`; quota and key errors explained; titles decoded safely.
- **Original and Karaoke modes**: mode-specific queries and ranking. Original
  ranks the artist's own, VEVO and "- Topic" channels first; Karaoke ranks
  karaoke, instrumental and backing-track uploads first.
- **View credit** under every embed: which channel gets the view and what that
  means (official upload, karaoke upload, or unknown for a pasted link), plus
  an "Open on YouTube" link.
- **Embed** (`video/youtube-api.ts`): the standard IFrame player, visible,
  YouTube controls on, at least 200 × 200 px. Pasting a link works without an
  API key.
- **Sync model**: `VideoClock` interpolates between 100 ms polls and corrects
  drift (snap above 300 ms, slew below); `SyncMap` maps video to chart time
  (anchors, piecewise-linear, offset); `VideoTransport` makes the video drive
  the practice session: loops seek the video, wait-for-me pauses it, tempo uses
  YouTube's rates, and YouTube's own play/pause/seek controls are followed.
- **Sync UI**: "First note now", tap-the-beat tempo fit, offset slider with
  ±10/±100 ms nudges, saved per song and video.
- **Scoring** against the video clock uses MIDI timestamps and the calibrated
  input offset, like internal-clock practice.

## Measured numbers

Clock tracking against simulated players (30 s, render at 60 Hz, poll at
100 ms; `scripts` measurement in the session scratchpad, mirrored by unit
tests):

| Player behaviour | Raw `getCurrentTime()` | `VideoClock` |
|---|---|---|
| Stale value, refreshed every ~250 ms | mean −126 ms, max 297 ms | mean +4.5 ms, sd 6.1 ms, max 14 ms |
| Stale value, refreshed every ~500 ms | mean −261 ms, max 593 ms | mean +2.0 ms, sd 5.2 ms, max 13 ms |
| API interpolates its own value | exact | exact |

In the browser (mock player with 250 ms stale polling), chart time stayed
within 60 ms of true video time after 2.5 s of play, and followed seeks and a
100 ms offset change.

## Tests

- Vitest: 109 unit tests (adds clock tracking for both player behaviours,
  rates, snaps; sync-map interpolation, inversion, tap fitting, start marking;
  URL parsing; official/karaoke detection and ranking; entity decoding;
  durations).
- Playwright: 20 end-to-end tests with a mocked IFrame API and Data API,
  adding: search parameters and ranking, the view credit, notes following
  play/seek/offset/pause/rate, first-note marking and scoring against the
  video clock, the no-key pasted-link path, and Karaoke mode.

## Known issues

- **Real YouTube playback could not be tested here**: the container's IP gets
  `errorCode: "auth"` from YouTube, so the live `getCurrentTime()` pattern and
  real embed latency are unverified (see D43).
- Wait-for-me with a video pauses the player when the hold point is reached;
  YouTube takes tens of milliseconds to react, so the video may run slightly
  past the chord.
- Tap fitting assumes a steady tempo within each tapped span.
- "Official" detection is a channel-name heuristic (D40).
